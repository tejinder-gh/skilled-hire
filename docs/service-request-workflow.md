# Service Request State Machine

```mermaid
stateDiagram-v2
  [*] --> DRAFT
  DRAFT --> SUBMITTED
  SUBMITTED --> QUALIFICATION_PENDING
  QUALIFICATION_PENDING --> QUALIFIED
  QUALIFIED --> SCHEDULING
  SCHEDULING --> SCHEDULED
  SCHEDULED --> CONTRACTOR_SEARCH
  CONTRACTOR_SEARCH --> ASSIGNED
  ASSIGNED --> TECHNICIAN_EN_ROUTE
  TECHNICIAN_EN_ROUTE --> TECHNICIAN_ARRIVED
  TECHNICIAN_ARRIVED --> ASSESSMENT_IN_PROGRESS
  ASSESSMENT_IN_PROGRESS --> QUOTE_PENDING
  QUOTE_PENDING --> QUOTE_SUBMITTED
  QUOTE_SUBMITTED --> QUOTE_APPROVED
  QUOTE_SUBMITTED --> QUOTE_REJECTED
  QUOTE_APPROVED --> WORK_SCHEDULED
  WORK_SCHEDULED --> WORK_IN_PROGRESS
  WORK_IN_PROGRESS --> CHANGE_ORDER_PENDING
  CHANGE_ORDER_PENDING --> WORK_IN_PROGRESS
  WORK_IN_PROGRESS --> COMPLETION_PENDING
  COMPLETION_PENDING --> COMPLETED
  COMPLETED --> CLOSED
  SUBMITTED --> CANCELLED
  SCHEDULED --> CANCELLED
  ASSIGNED --> CANCELLED
  QUOTE_SUBMITTED --> CANCELLED
  WORK_IN_PROGRESS --> ON_HOLD
  ON_HOLD --> WORK_IN_PROGRESS
  state "Any active state" as ACTIVE
  ACTIVE --> DISPUTED
  DISPUTED --> CLOSED
```

Transitions are centrally validated and append an `AuditEvent`. The API rejects arbitrary status writes. Quote approval freezes the accepted version; follow-up pricing must use a change order.
